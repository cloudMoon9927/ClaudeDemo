# 基金实时估值辅助工具 - 系统架构设计文档

## 一、架构设计总览

### 1.1 核心设计原则

| 原则       | 说明                            |
| -------- | ----------------------------- |
| **隐私优先** | 持仓数据、截图OCR全流程本地化处理，绝不上传云端     |
| **计算分离** | 估值演算、行情聚合等重计算在服务端完成，前端专注展示与交互 |
| **弹性伸缩** | 交易时段高并发，非交易时段低负载，架构需支持动态扩缩容   |
| **多端预留** | 核心服务层与前端解耦，API设计兼容后续小程序接入     |
| **高可用**  | 全年服务可用率 ≥ 99.5%，交易日高峰无宕机      |

## 二、客户端架构详细设计

### 2.1 技术选型

| 维度            | 选型                                    | 说明                                         |
| ------------- | ------------------------------------- | ------------------------------------------ |
| **框架**        | React 18                              | 生态丰富，hooks模式适合高频状态更新                       |

| **本地加密**      | Web Crypto API (AES-256-GCM)          | 浏览器原生，零依赖，高性能                              |
| **OCR引擎**     | PaddleOCR.js (WASM)                   | 离线识别，支持中文，精度高                              |
| **Worker**    | Web Worker                            | 将OCR、加密等耗时任务移出主线程                          |

#### 估值计算性能优化策略

go

// 伪代码：指数基金估值计算（高优先级，低延迟）
func CalculateIndexFundValuation(fund *IndexFund) *Valuation {
    // 1. 从本地内存获取成分股权重映射（启动时加载，定时刷新）
    weights := fund.GetConstituentWeights()

    // 2. 从本地内存获取实时价格（Kafka流预加载到ConcurrentMap）
    prices := realtimePriceCache.MGet(weights.GetStockCodes())
    
    // 3. 向量化加权计算（利用SIMD或批量运算）
    estimatedNAV := vectorizedDotProduct(weights, prices)
    
    // 4. 与ETF IOPV交叉校验
    iopv := iopvCache.Get(fund.IOPVCode)
    if abs(estimatedNAV - iopv) / iopv > 0.005 {
        // 偏差过大，使用IOPV校准
        estimatedNAV = iopv
    }
    
    return &Valuation{
        NAV:      estimatedNAV,
        Change:   (estimatedNAV - fund.PrevNAV) / fund.PrevNAV,
        Confidence: High,
    }

}

## 四、数据架构设计

### 4.1 数据分层策略

| 数据层          | 存储            | TTL    | 说明                |
| ------------ | ------------- | ------ | ----------------- |
| **L0: 实时行情** | Redis (内存)    | 交易时段有效 | 个股价格、指数点位、IOPV    |
| **L1: 估值结果** | Redis         | 10秒    | 最新估值快照，供API查询     |
| **L2: 时序行情** | InfluxDB      | 永久     | 历史行情、估值记录，支撑回溯    |
| **L3: 业务数据** | MySQL 8.0     | 永久     | 基金信息、用户自选ID、持仓元数据 |
| **L4: 本地存储** | 浏览器 IndexedDB | 用户手动清除 | 加密持仓数据、自选列表缓存     |

## 九、技术风险与应对

| 风险                 | 影响      | 应对措施                          |
| ------------------ | ------- | ----------------------------- |
| **估值偏差过大引发用户投诉**   | 用户信任度下降 | 置信度标签显著展示；偏差超标自动推送提示；免责声明不可关闭 |
| **交易时段流量峰值**       | 服务雪崩    | 多级缓存+限流熔断+K8s HPA弹性伸缩         |
| **WebSocket连接数爆炸** | 服务端压力   | 按订阅频道合并推送；只推送用户自选基金估值；连接数上限监控 |
| **OCR识别准确率不足**     | 用户体验差   | 多平台模板适配；提供手动修正入口；低置信度字段高亮提示   |
| **数据源中断**          | 估值无法更新  | 多数据源备份；降级方案（使用指数替代）；状态栏明确提示   |
